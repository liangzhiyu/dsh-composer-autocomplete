# 性能与延迟

## 0.2.3：快速模式与候选复用

- 新浏览器默认停顿 150 ms，允许 100–5000 ms；旧停顿保留，可手动选择 150 ms。快速模式下回复后的等待为 200 ms，完整模式仍为 600 ms。
- 快速模式最多使用 6 条消息、4000 个上下文字符、2 条工具记录和 96 个输出 token，生成一条候选；完整模式使用原有配置上限。首条完整行到达后快速模式取消剩余生成，保留已完成结果。
- 顺着已有完整候选继续输入时，只在会话相同、原草稿前缀相同、输入内容准确匹配候选且光标位于末尾时复用。保留英文词内的字面后缀，不拼接多余空格。组合输入、不同内容、运行中的 Agent 和会话切换不走该复用。
- 快速与完整模式的结果及上下文缓存分别隔离，保持 TTL、容量限制和取消保护。

同一个本地模型保持初始等待 80 ms、每 5 字符片段间隔 25 ms。每组 6 次，每次草稿不同，避开宿主结果缓存：

| 版本／模式 | 输入停顿 | 首次灰字 | 可采纳 |
| --- | ---: | ---: | ---: |
| 0.2.2 完整 | 300 ms | 405 ms | 426 ms |
| 0.2.3 快速 | 300 ms | 406 ms | 428 ms |
| 0.2.3 快速 | 150 ms | 256 ms | 277 ms |
| 0.2.3 快速 | 100 ms | 205 ms | 235 ms |

相同 300 ms 停顿时，本地模型的首条响应没有明显变化；默认 150 ms 的改进主要来自减少固定等待。候选复用的六次英文逐字输入中位数为 11 ms，没有新增预测请求。较少上下文、单候选对真实云模型的收益尚未测量，不据此声称云端提速比例。

原始记录：[0.2.2 基线](benchmarks/latency-0.2.2.json)、[0.2.3 新请求](benchmarks/latency-0.2.3.json)、[候选复用](benchmarks/speed-results.json)。

如果实际瓶颈在云模型首 token 或思考时间，可通过 profile 的 `provider`／`model` 配置为补全选择单独的快速模型，主对话的模型配置不变。更短停顿可能增加请求频率，可根据实际输入节奏调整。

## 0.2.0 优化说明

## 发现的问题与改进

| 原有行为 | 修改 | 取舍 |
| --- | --- | --- |
| 首条候选已经完成，仍要等整组候选结束才可 Tab | 宿主对换行结束的完整候选做清洗后发送 candidates 事件，客户端立即允许采纳 | 半句话仍不可采纳；未采纳的建议在断流时清除 |
| 同一轮对话每次换草稿都重新整理完整消息投影 | 以会话 ID 和序号缓存已整理的上下文 | 序号变化或缓存到期后重新整理，保留有界缓存 |
| 模型回复 NONE 后，重复请求仍消耗一次模型调用 | 成功的空结果也在有效期内缓存 | 临时错误、无路由、未完成流不缓存 |
| 页面隐藏后模型请求仍继续 | 隐藏时取消请求并清除灰字，恢复时重新检查草稿 | 已发生的模型用量仍以提供商规则为准 |
| SSE 无新片段时，通用读取器可能不能及时响应取消 | AbortSignal 主动取消 reader，结束后移除监听器 | 原稿始终保留 |
| 新浏览器默认停顿 600 ms | 默认改为 300 ms，保留 200–5000 ms 调整 | 更短停顿可能增加请求次数；已有偏好不覆盖 |

## 本地链路测量

使用同一个确定性本地模型，设定初始等待 80 ms、每个 5 字符片段间隔 25 ms；正常候选文本相同，未启用慢尾部测试分支。请求通过真实 Harness LLM、HTTP/SSE 和原生输入框，未拦截预测接口。

每组 6 次，使用不同草稿避开结果缓存。起点为 MutationObserver 观察到编辑器文本变化，记录首次显示灰字与 Tab 提示出现的动画帧时间。结果为中位数：

| 版本 | 输入停顿 | 灰字首次出现 | 首条可采纳 |
| --- | ---: | ---: | ---: |
| 0.1.0 | 600 ms | 702 ms | 862 ms |
| 0.2.0 | 600 ms | 705 ms | 727 ms |
| 0.2.0 | 300 ms | 404 ms | 425 ms |
| 0.2.0 | 200 ms | 307 ms | 326 ms |

相同 600 ms 停顿下，提前采纳主要消除了等待其他候选的尾部时间；默认值调整另外减少了 300 ms 的输入停顿等待。不能据此推断真实云模型的响应速度、质量或成本变化。

原始数据：[0.1.0](benchmarks/baseline-fixture.json)、[0.2.0](benchmarks/optimized-fixture.json)。运行隔离实例后，可执行 `pnpm benchmark` 复测；`DSH_BENCH_DELAYS=600,300,200` 可指定要测的停顿设置。

## 验证范围

50 项单元／组件回归和 12 项真实 Harness 浏览器检查。宿主测试明确验证首条完整候选在最终 done 之前发布，浏览器测试在剩余候选刻意延迟 800 ms 时按 Tab 采纳，并检查未自动发送。操作系统原生输入法候选窗、付费云模型与 Electron 载体未实机验证。
